The problem

Lite Touch 耗人力，經典 Zero Touch 耗機房與頻寬

Lite Touch burns labor. Classic Zero Touch burns the datacenter and the pipe.

兩者都在「灌映像」。差在人要不要點精靈、以及 N 台電腦要不要各從同一台伺服器拉一份完整 WIM。

Both still image PCs. The difference is whether a person clicks a wizard, and whether N PCs each pull a full WIM from one server.

開源基底
Open-source base

站在 OSDCloud 上，而不是從零重寫成像引擎

Stand on OSDCloud. Do not rewrite the imaging engine.

OSDCloud 是 David Segura／OSDeploy 的開源 PowerShell 部署框架，社群與文件成熟，PowerShell Gallery 可安裝。Winception 用它處理 WinPE 套用 Windows，再補上可帶走的主機、Web 與 P2P。

OSDCloud is David Segura / OSDeploy’s open-source PowerShell deployment framework, with a mature community, docs, and a PowerShell Gallery package. Winception uses it to apply Windows from WinPE, then adds a portable host, Web, and P2P.

OSDCloud 本身就擅長的事

What OSDCloud already does well

  • WinPE 裡下載或套用 Windows 10／11
  • Dell、HP、Lenovo、Surface 官方 Driver Pack

  • 沒有官方包時可走 Microsoft Update Catalog
  • Download or apply Windows 10 / 11 from WinPE
  • Official Dell, HP, Lenovo, and Surface driver packs
  • Get-MyDriverPack matches SMBIOS make / model
  • Falls back to Microsoft Update Catalog when no OEM pack exists

Winception 加在上面的事

What Winception adds on top

  • 本機 WIM 快取，不依賴每台去抓 Microsoft ESD
  • Torrent P2P 讓多台互傳映像
  • Web Console、profile、軟體目錄、Evidence
  • PXE Secure Boot、既有 DHCP 配對、USB 離線
  • A local WIM cache — PCs do not each fetch a Microsoft ESD
  • Torrent P2P so many clients share the image
  • Web Console, profiles, software catalog, Evidence
  • PXE Secure Boot, existing-DHCP pairing, offline USB

執行契約

The run contract

  • 順序由 profile 的 installSequence 決定
  • 任一步失敗、缺檔或逾時 → fail-fast，後續不跑
  • 登入後以 SYSTEM 任務安裝，畫面顯示即時耗時
  • Evidence 只記步驟名、狀態、秒數，不含秘密
  • Order comes from the profile installSequence
  • Any miss, failure, or timeout is fail-fast; later steps do not run
  • A SYSTEM task installs after logon; the screen shows live elapsed time
  • Evidence records step name, status, and seconds — never secrets

需要外網的安裝放在登入後序列；映像套用階段只連 Winception 主機。

Internet-dependent installs belong in the post-logon sequence; image apply only talks to the Winception host.

How to read this

  • 這是 host 上傳量模型，不是保證總部署分鐘數線性下降
